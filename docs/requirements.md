# 要件定義書 — 空き時間コピーくん

## 1. 概要

| 項目 | 内容 |
|---|---|
| 製品名 | 空き時間コピーくん |
| 種別 | Google Chrome 拡張機能(Manifest V3) |
| バージョン | 0.4.0 |
| 対象サイト | `https://calendar.google.com/*` |
| 目的 | クライアントとの日程調整メール/チャットに貼り付ける「空き時間一覧」を素早く作成する |

## 2. 背景・課題

- 日程調整のたびに、Google カレンダーを目視確認しながら空き時間を手入力でまとめる作業が発生し、手間がかかる。
- Google Calendar API や OAuth 連携を使うと、認可設定やアカウント権限の管理が必要になり導入のハードルが上がる。
- カレンダーの予定表示を自動解析する方式は、Google 側の DOM 構造・表記が変わるたびに壊れるリスクが高い(後述の非機能要件を参照)。

## 3. 用語定義

| 用語 | 定義 |
|---|---|
| 枠(スロット) | ユーザーが選択した1つの空き時間帯(開始日時・終了日時の組) |
| 一覧 | 追加済みの枠をまとめたリスト。パネル内に表示され、ブラウザに保存される |
| パネル | カレンダー画面右下に常駐するフローティングUI |
| コピーテキスト | 一覧を整形した、クリップボードにコピーするための箇条書き文字列 |

## 4. スコープ

### 4.1 対象に含むもの

- Google カレンダー(`calendar.google.com`)上で動作する Chrome 拡張機能
- ドラッグ選択した時間帯をポップアップのテキストから読み取り、一覧に追加する機能
- 一覧の表示・削除・全クリア
- 一覧を整形してクリップボードにコピーする機能
- 一覧のブラウザローカルへの永続化(リロード後も保持)
- パネルの表示/最小化の切り替え

### 4.2 対象外とするもの

- Google Calendar API・OAuth 等によるカレンダーデータへの直接アクセス
- 予定の自動検出(DOM自動スキャンによる空き時間計算)
- 相手への自動送信(メール送信・チャット送信などの連携)
- カレンダー以外のサービス(Outlook等)への対応
- 複数ユーザー間でのリアルタイム共有

## 5. 機能要件

### 5.1 時間帯の追加

| ID | 要件 |
|---|---|
| F-01 | ユーザーがカレンダー上でドラッグ選択すると、Google カレンダー標準の予定作成ポップアップが表示される |
| F-02 | パネルの「＋ 選択中の時間を追加」ボタン押下時、画面上のポップアップ要素のテキストから日付・開始時刻・終了時刻を抽出する |
| F-03 | 抽出に成功した場合、一覧に新しい枠として追加し、トースト通知で「追加しました」と表示する |
| F-04 | 抽出に失敗した場合、エラーメッセージを表示し、再度ドラッグ選択してから押し直すよう促す |
| F-05 | 日付は「○月○日」形式を認識し、今日の日付に最も近い年を自動推定する(年をまたぐ誤判定を防止) |
| F-06 | 時間帯は「HH:MM + 区切り文字(〜/～/~/-/–/—) + HH:MM」、および午前/午後表記を認識する |
| F-07 | 終了時刻が開始時刻以前の場合は無効な枠として追加しない |

### 5.2 一覧の管理

| ID | 要件 |
|---|---|
| F-10 | 追加した枠は開始日時の昇順でパネルに一覧表示する |
| F-11 | 各枠は「・8/18(火) 10:00〜11:00」の形式で表示する |
| F-12 | 各枠の右側に「×」ボタンを設け、個別削除できる |
| F-13 | 「クリア」ボタンで一覧を全件削除できる(件数0件のときは非活性) |
| F-14 | 一覧は `chrome.storage.local` に保存し、ページ再読み込み後も復元する |
| F-15 | 一覧の件数をパネルのタイトル横に表示する(例:「(3)」) |

### 5.3 コピー機能

| ID | 要件 |
|---|---|
| F-20 | 「コピー」ボタン押下で、一覧を整形したテキストをクリップボードにコピーする(件数0件のときは非活性) |
| F-21 | 同じ日付の枠は1行にまとめ、時間帯を「、」区切りで連結する(例:「・8/18(火) 10:00〜11:00、14:00〜15:00」) |
| F-22 | `navigator.clipboard` が利用できない場合、`textarea` + `execCommand("copy")` によるフォールバックでコピーする |
| F-23 | コピー成功時はトースト通知で「コピーしました」と表示する |

### 5.4 パネルのUI/表示制御

| ID | 要件 |
|---|---|
| F-30 | パネルは Shadow DOM で構築し、Google カレンダー本体の CSS の影響を受けない/与えないようにする |
| F-31 | パネルはヘッダー部分のクリックで「表示/最小化」を切り替えられる |
| F-32 | 拡張機能のツールバーアイコンのクリックでも「表示/最小化」を切り替えられる(service worker 経由でメッセージ中継) |
| F-33 | 最小化状態は `chrome.storage.local` に保存し、次回表示時も維持する(初回利用時はデフォルトで最小化) |
| F-34 | 最小化中は半透明(不透明度50%)で表示し、マウスホバー時に不透明度100%に戻す |

## 6. 非機能要件

| ID | 要件 |
|---|---|
| N-01 | ビルドツール・パッケージマネージャに依存しない(素の JS のみ、`npm install` 不要) |
| N-02 | 必要な権限は `storage` のみとし、カレンダーデータへの読み取り専用アクセスや外部送信は行わない |
| N-03 | Google カレンダーの DOM 構造変更に対する耐性を優先し、個々の予定チップの `aria-label` 解析には依存しない設計とする |
| N-04 | 拡張機能の再読み込み後、既存タブで発生しうる `Extension context invalidated` エラーを検知し、ユーザーにページ再読み込みを促す表示へ切り替える(未捕捉エラーを出さない) |
| N-05 | 日本語 UI を前提とする(多言語対応は対象外) |

## 7. 制約・既知の限界

- 検出(F-02)は、ドラッグ選択直後に表示される「日付+時間帯を含む小さなポップアップ」を対象にした文字列マッチングであり、Google 側のポップアップ文言パターンが変わると読み取りに失敗する可能性がある。
- 複数の候補要素が同時に日付・時間帯パターンにマッチした場合、最初に見つかったものを採用する(優先順位付けは行わない)。
- アイコン画像は単色のプレースホルダーであり、正式デザインへの差し替えは別途対応が必要。

- コピー文言(記号・区切り文字・曜日表記)のカスタム設定
- 正式アイコンへの差し替え
